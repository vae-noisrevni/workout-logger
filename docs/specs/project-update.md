# Обновление Workout Logger: спека и тикеты

Дата: 16 ноября 2026. Статус: согласовано пользователем в ответах 1–21. T01–T11 реализованы в ветке `codex/project-update`; T12: автоматическая проверка и ревью выполнены, нативная приёмка требует Android-устройства.

## 1. Объём и приоритет документов

Целевая платформа обновления — Android. Отдельная адаптация и приёмка на iOS не входят в объём.

В обновление входит реализация [statistics.md](./statistics.md): избранное, статистика, месячный прогресс, график за 12 месяцев и калькулятор подходов во всех описанных точках входа. Этот документ дополняет ту спеку и имеет приоритет при расхождениях.

Новые зависимости не добавляем без отдельного вопроса. Работа идёт последовательно по тикетам, без коммитов и пуша; изменения остаются unstaged. Перед реализацией большой задачи нужна отдельная ветка с префиксом `codex/`.

Экспорт пресетов, замеров веса и общий бэкап не входят в обновление. Существующий импорт/экспорт сохраняется; опциональное `favorite` добавляется согласно старой спеке. Связь с пресетом не обещается сохранять при переносе через существующие файлы истории.

## 2. Исходное состояние кода

- Expo SDK 57; React Native 0.86.3; Expo Router; локальная SQLite.
- Вкладки: тренировка, упражнения, история. Статистика и избранное пока описаны только в старой спеке.
- Действующая схема БД находится в `src/db/init.ts`; `src/db/schema.ts` устарел.
- Вес подхода — число в кг; для `assisted` это вес помощи, для `bodyweight` поле скрыто.
- Черновик и режим редактирования сохраняются через AsyncStorage в `src/hooks/useWorkoutDraft.ts`.
- Новое упражнение сейчас получает подход 10 повторений × 0 кг. Загрузка пресета должна создавать упражнения без этого подхода.
- Удаление упражнения из справочника сейчас каскадно удаляет связанные записи упражнений из истории. Это существующее поведение не расширяем попутно; влияние на пресеты указано ниже.
- Даты тренировок сохраняются в ISO с переводом локальной даты в UTC. День недели и месяц рассчитываются по локальной дате, а не по UTC-подстроке.
- Перед началом работы уже были изменения в `app.json` и неотслеживаемый каталог `docs/specs/`. Их не перезаписываем и не считаем своими изменениями.

## 3. Согласованное поведение

### 3.1. Вес упражнения в кг и lb

- В форме подходов есть переключатель кг/lb. Выбор запоминается отдельно для каждого упражнения и переживает перезапуск.
- Для `weighted` и `assisted` ввод, кнопки −/+ и подпись поля используют выбранную единицу. Для `bodyweight` переключателя нет.
- Шаг кнопок: 2.5 кг или 2.5 lb.
- При вводе в lb сразу виден эквивалент в кг с точностью отображения до двух знаков после запятой.
- Коэффициент: `1 lb = 0.45359237 kg`. В черновике, БД, экспорте истории и расчётах остаются кг; точность хранения не обрезается до двух знаков.
- Переключение единиц меняет представление, а не физическую нагрузку. Повторное открытие и смена единиц не должны накапливать округление.
- История и статистика показывают кг. Калькулятор старой спеки остаётся в кг, его применение корректно отображается в форме с выбранной единицей.
- Для существующих упражнений единица по умолчанию — кг.

### 3.2. Справочник упражнений

Убираем лишние 60 px над поиском в `src/app/(tabs)/exercises.tsx`. Поиск располагается под заголовком с обычным небольшим отступом, без наложения на системную строку.

### 3.3. История: день недели и поиск

- Рядом с датой отображается русский день недели, например `пн, 16 ноября 2026 г.`.
- Поиск по части названия упражнения, без учёта регистра и крайних пробелов.
- Результат — обычные карточки тренировок, содержащих совпавшие упражнения. В карточке дополнительно видны названия совпадений.
- Карточка показывается один раз, даже если совпало несколько упражнений. Порядок остаётся от новых тренировок к старым.
- Пустой запрос возвращает всю историю. Для отсутствующих совпадений отдельное сообщение, отличающееся от пустой истории.
- Открытие, редактирование и удаление карточек сохраняют существующее поведение.
- Экспорт выгружает всю историю независимо от поискового запроса.

### 3.4. Лучший подход последней тренировки

- Подсказка видна в форме подходов при добавлении и повторном открытии упражнения.
- Берётся последняя по дате сохранённая тренировка с этим упражнением, а не рекорд за всё время и не только тренировки одного пресета.
- В подсказке — лучший подход этой тренировки: вес, повторы, дата; для `bodyweight` только повторы и дата.
- Критерий лучшего подхода по старой спеке: `weighted` — максимальный вес, `assisted` — минимальная помощь, `bodyweight` — максимальное число повторений.
- Подсказка ничего автоматически не подставляет в подходы.
- Без истории показывается «Предыдущих результатов нет».
- Подтверждённая детализация: при равном весе/помощи выбираем больше повторений; при полном равенстве первый подход. При одинаковой дате тренировок — больший ID. При редактировании исключаем саму редактируемую тренировку из поиска подсказки.

### 3.5. Объём в карточках избранного

- Дополнительно к лучшему показателю за всё время и месячному прогрессу из старой спеки показываем объём последней по дате тренировки с упражнением и дату этой тренировки.
- `weighted`: сумма `weightKg × reps` по всем подходам упражнения; подпись «Тоннаж», единица кг.
- `bodyweight` и `assisted`: сумма повторений по всем подходам; подпись «Объём», единица повторения.
- Вес тела не участвует в этих расчётах. Увеличение веса помощи не трактуется как рост полезного тоннажа.
- Если истории нет — «Нет данных», а не выдуманный нулевой результат.

### 3.6. Замеры веса тела

- В статистике доступны добавление и исправление отдельных замеров с датой и положительным конечным весом в кг. Замер не привязан к тренировке.
- Небольшой список замеров расположен в статистике; ввод поддерживает дробные значения с точкой или запятой.
- В блоке «Тренировок в месяц» показываем последний по дате вес тела и разницу с предыдущим по дате замером, с датами обоих замеров.
- При одном замере показываем вес без разницы, при отсутствии — предложение добавить первый замер.
- Разница: последний вес минус предыдущий, со знаком. Направление изменения веса тела не окрашиваем как успех/неудачу: цель пользователя неизвестна.
- Исправление даты или веса пересчитывает порядок и разницу.
- Это дополнительное содержимое месячного блока. График тренировок за 12 месяцев и прогресс избранных упражнений из старой спеки сохраняются.

### 3.7. Месячная анимация

- В блоке «Тренировок в месяц» мягко пульсирует фоновый оттенок, напоминающий сердцебиение.
- Количество сохранённых тренировок текущего календарного месяца: 0–4 — красный, 5–7 — оранжевый, 8 и больше — зелёный.
- Считаются тренировки, а не дни посещений; две тренировки одного дня — две записи.
- Количество и цвет обновляются после сохранения, удаления, импорта, изменения даты тренировки и при переходе в новый месяц.
- Текст читается в обеих темах. Анимация не работает в фоне или на неактивном экране; при системном уменьшении движения остаётся статичный оттенок.

### 3.8. Системная строка Android

- В светлой теме под временем и батареей тёмная подложка со светлыми системными значками.
- Заголовок самого экрана сохраняет светлую тему. В тёмной теме контраст также сохраняется.
- Проверяем переключение темы, переходы между вкладками и открытие шторок.
- Конкретный способ реализации выбираем после проверки документации SDK 57 и актуальных ограничений Android edge-to-edge; устаревшие настройки цвета status bar не используем вслепую.

### 3.9. Пресеты

- Пресет — название и упорядоченный список упражнений. Количество подходов, веса и повторы в нём не хранятся.
- Можно создать/изменить пресет на отдельном экране и сохранить состав текущей тренировки как новый пресет.
- «Понедельник», «Среда», «Пятница» — примеры пользовательских пресетов; автоматического расписания и автозапуска по дню недели нет.
- На экране тренировки доступен быстрый выбор пресета. В пустой черновик он загружается одним нажатием, без дополнительного подтверждения.
- При непустом черновике или активном редактировании истории требуется подтверждение замены. Отмена сохраняет текущий черновик целиком.
- Загрузка пресета начинает новую тренировку, а не редактирует прошлое выполнение. Упражнения создаются без подходов; первый подход добавляется вручную.
- В историю сохраняются только упражнения с заполненными подходами. Полностью пустую тренировку завершить нельзя; счётчик в форме завершения учитывает только сохраняемые упражнения.
- Автоматического переноса прошлых весов/повторов нет. Ориентир — подсказка из п. 3.4.
- У тренировки сохраняются ID пресета и снимок названия на момент тренировки; снимок показывается в истории и не меняется при переименовании пресета.
- Редактирование сохранённой тренировки сохраняет её происхождение. Изменения упражнений текущего выполнения не переписывают состав самого пресета.
- Состав, порядок, происхождение и снимок названия активного черновика переживают перезапуск приложения.
- Подтверждённая детализация: удаление пресета не удаляет тренировки; для сохранения ID используем архивирование пресета. Архивный пресет скрыт из выбора новых тренировок, но доступен для разрешения существующих связей.
- Подтверждённая детализация: удалённое из справочника упражнение исключается из состава пресета. Пустой после этого пресет остаётся доступен для редактирования, но не для запуска.

## 4. Предлагаемая техническая структура

Это план реализации, а не требование воспроизводить сигнатуры до изучения соответствующего тикета.

| Область | Файлы / данные |
|---|---|
| Избранное, статистика, калькулятор | Файлы и контракты из `statistics.md` |
| Единица упражнения | `exercises.weight_unit`, тип и репозиторий упражнений; `utils/weight.ts`; `SetsSheet`, при необходимости `NumberStepperField` |
| Последние результаты | Общий запрос в `db/stats.ts`; выбор подхода и объёма в `utils/stats.ts`; переиспользование в подсказке, карточках и калькуляторе |
| История | `app/(tabs)/history.tsx`, `utils/date.ts` |
| Вес тела | `body_weight_entries(id, date, weight_kg)`, репозиторий, типы, хук и небольшие компоненты ввода/списка |
| Пресеты | `workout_presets(id, name, archived)`, `workout_preset_exercises(preset_id, exercise_id, sort_order)`; типы, репозиторий, хук, экран и быстрый выбор |
| Происхождение тренировки | Nullable `workouts.preset_id`, `workouts.preset_name`; расширение типов, чтения, создания и обновления |
| Черновик | `useWorkoutDraft`, контекст, сериализация происхождения вместе с составом; совместимое чтение старого черновика |
| Тема и системная строка | `app/_layout.tsx`, при необходимости layout вкладок и существующий ThemeContext |

Миграции выполняются в `db/init.ts`, сохраняют существующие тренировки и упражнения и допускают повторный запуск. Состав пресета и сохранение тренировки записываются транзакционно. Для веса тела нужна собственная инвалидация; пресеты должны реагировать также на изменение справочника. Периоды и даты считаются локально.

## 6. Проверки и ограничения

- Перед изменениями Expo/React Native API читаем документацию Expo SDK 57 и нужные страницы из индекса Expo.
- Новых тестовых зависимостей не добавляем без разрешения. Для чистой логики используем доступные средства; небольшое число проверок реальных сценариев вместо большого набора однотипных тестов.
- Для написанного и запускаемого теста временно ломаем проверяемую логику, убеждаемся в падении и восстанавливаем код. Чужие правки при этом не затрагиваем.
- После кода каждого тикета запускаем `expo lint` и `tsc --noEmit` доступным менеджером пакетов. Форматтер на файлы/проект не запускаем. Если lint требует установки зависимости — сначала вопрос пользователю.
- Проверка UI через web не доказывает работу Android status bar и нативных шторок. Если Android-устройство/эмулятор недоступны, это ограничение явно указывается в отчёте, без заявления о пройденной нативной проверке.
- Перед запуском dev-сервера проверяем, нет ли уже работающего экземпляра.
- После изменений общих расчётов, миграций и черновика выполняем регрессионное ревью затронутых сценариев.
- На этапе подготовки этой спеки код не менялся; lint/typecheck не запускались, поскольку проверять изменения реализации пока нечего.

## 7. Подтверждённая детализация

Основные продуктовые решения согласованы в ответах 1–18. Следующие детали подтверждены ответами 19–21:

1. Замеры: один замер на календарную дату; повторный ввод предлагает исправить существующий. Дата не позже сегодняшней. Удаление замера доступно с подтверждением и пересчитывает разницу.
2. Пресеты: отдельная вкладка «Пресеты»; создание из текущей тренировки копирует также упражнения без подходов. Названия свободные; «Понедельник», «Среда», «Пятница» пользователь создаёт сам. Без дублей упражнений внутри пресета; порядок можно менять. Пустой пресет нельзя сохранить вручную или запустить.
