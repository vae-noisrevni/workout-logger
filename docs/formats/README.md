# Форматы импорта и экспорта

Приложение умеет выгружать и загружать **справочник упражнений** и **историю тренировок** в двух форматах: JSON и CSV. Тип файла определяется по расширению (`.json` / `.csv`), кодировка UTF-8 (BOM допускается).

| Данные | JSON Schema | Пример JSON | Пример CSV |
|---|---|---|---|
| Упражнения | [exercises.schema.json](exercises.schema.json) | [examples/exercises.json](examples/exercises.json) | [examples/exercises.csv](examples/exercises.csv) |
| История | [history.schema.json](history.schema.json) | [examples/history.json](examples/history.json) | [examples/history.csv](examples/history.csv) |

**Порядок импорта:** сначала упражнения, потом история — история ссылается на упражнения по названию.

## Упражнения

### JSON
Объект `{ "version": 1, "exercises": [...] }` (допускается и «голый» массив). Поля упражнения:

| Поле | Обязательно | Значения |
|---|---|---|
| `name` | да | непустая строка |
| `type` | нет (`weighted`) | `weighted` — с отягощением, `assisted` — с облегчением, `bodyweight` — свой вес |
| `description` | нет (пусто) | строка |
| `color` | нет (`#a0d37f`) | `#RRGGBB` |
| `favorite` | нет (`false`) | `true` / `false` (в CSV также `1` / `0`) — избранное, участвует в статистике |

### CSV
Заголовок `name,type,description,color,favorite`. Обязательна только колонка `name`, порядок колонок произвольный, лишние колонки игнорируются. Одна строка = одно упражнение.

### Правила импорта
- Каждая запись **создаёт новое** упражнение, даже если с таким названием уже есть: повторный импорт того же файла даст дубли.
- Если хоть одна запись невалидна, импортируется **ничего**, пользователю показывается список ошибок (с номерами строк).

## История тренировок

### JSON
Объект `{ "version": 1, "workouts": [...] }` (допускается и «голый» массив). Структура: `workout → exercises[] → sets[]`.

| Поле | Обязательно | Значения |
|---|---|---|
| `workouts[].name` | да | непустая строка |
| `workouts[].date` | да | `ГГГГ-ММ-ДД` или ISO 8601 дата-время |
| `workouts[].comment` | нет | строка |
| `exercises[].name` | да | название упражнения из справочника |
| `exercises[].type` | нет | только для информации, при импорте игнорируется |
| `sets[].reps` | да | целое ≥ 1 |
| `sets[].weight` | да | число ≥ 0, кг |

### CSV
**Одна строка = один подход.** Колонки:

| Колонка | Обязательно | Описание |
|---|---|---|
| `date` | да | `ГГГГ-ММ-ДД` или ISO 8601 |
| `workout` | да | название тренировки |
| `comment` | нет | комментарий; достаточно указать в любой строке тренировки (берётся из первой) |
| `exercise` | да | название упражнения |
| `type` | нет | игнорируется при импорте |
| `set` | нет | номер подхода, игнорируется: порядок подходов берётся из порядка строк |
| `reps` | да | целое ≥ 1 |
| `weight_kg` | да | число ≥ 0; десятичный разделитель `.` или `,` |

Тренировка определяется парой **(`date`, `workout`)**: строки с одинаковой парой попадают в одну тренировку, упражнения идут в порядке первого появления. Две разные тренировки с одинаковой датой и названием в CSV склеятся — используйте JSON или разные названия.

Разделитель — запятая; файлы с `;` (Excel в русской локали) определяются автоматически. Ячейки с запятой, `;`, кавычками и переводами строк берутся в двойные кавычки (`"` внутри удваивается `""`).

### Правила импорта
- Упражнения сопоставляются со справочником **по названию без учёта регистра**. Если хотя бы одного нет в справочнике — отклоняется **весь файл**, в сообщении перечислены недостающие названия.
- Тренировка, у которой совпали **календарный день и название** (без учёта регистра) с уже имеющейся в истории, **пропускается**. Повторный импорт того же файла безопасен.
- Невалидные записи (дата, `reps`, `weight` и т. д.) отклоняют весь файл со списком ошибок.

## Проверка файла
JSON можно проверить любым валидатором JSON Schema 2020-12, например:

```bash
npx ajv-cli validate --spec=draft2020 -s docs/formats/history.schema.json -d my-history.json
```
